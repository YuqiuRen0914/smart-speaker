## 当前 ESP32 实现

- 从壁纸空白处左滑进入应用，打开「助手 → 宠物动作」。可用旋钮或上下滑动选择 114 段动作，确认后回壁纸首页点播一次。「睡觉 / 叫醒」依次播放入睡、循环和起身；点角色可叫醒，入睡被打断时直接回待机。睡眠状态保留至离开菜单后回桌面，不跨重启。语音和真实提醒继续使用现有服务，睡眠期间暂停随机动作。
- 点击触发 Q 弹及动画，从角色身上起手可向任意方向拖动；快速松手根据短程触摸速度甩出。先轻点一次，300 ms 内在附近再次按住拉动，松手触发反方向弹弓。慢速松手弹回，边界反射带挤压。从壁纸空白处左滑进入应用，点空白不改变音乐；长按保留原单轮小智。旋钮、实体键和音乐页继续控制播放。
- MPU6050 倾斜仍使用原姿态路径。摇动另检测短时间内的两次反向加速度峰值，过滤重复样本并设冷却期；只在可互动、未睡眠且不拖动时触发。没有接触觉马达。初始阈值已通过主机用例，物理方向、灵敏度和误触率待上板调整。
- 闲置约 35–60 秒选一个安全动作，不连续抽中同一项；其中一个会显示短句。短句为本地文字，不开麦、不自动朗读、不抢歌词。小智聆听／思考／说话使用已有会话状态；说话时可显示服务返回的实际短字幕。首页的提醒只读取原时间所有者已经产生的待处理记录，不标记处理、不新建数据，也不额外播放音频。
- 不接入多开、余额查询或 DSH 工作状态联动；对应动作仍在原件和手动点播目录。系统托盘、PC 透明悬浮窗和多宠物碰撞随平台和范围排除。

## 安装与资源生命周期

1. 将本地 ZIP 的 `characters/` 解压到 SD 根目录。包入口为 `characters/dsh-pet/pet-v2.idx`，动画位于 `frames-v2/`。壁纸首页首次成功读取后，动作目录才可用。没有动画包时仍显示内置待机图。
2. `python3 tools/resource-tools/prepare_dsh_pet.py .local/dsh-pet-sd-v2` 从固定 WebM 离线转换；FFmpeg 需含 libvpx-vp9。以 12 fps 采样，输出 120×120 RGB565，保留原素材并在派生包中合成黑底。前五段沿用首版裁切，其他片段依据采样帧的 alpha 范围扩大裁切并补黑边，避免压扁宽动作。清单记录源摘要、裁切、帧数、派生摘要和授权。
3. V2 含 114 段、13,442 帧、1,123 个分段，共 387,183,608 bytes（不含清单／声明）。每段文件最多一秒，限制 FAT 跳读时最多遍历约 338 KiB；每次打开只读取指定帧并立即关闭，ESP32 用 `fstat` 核对长度，帧以 CRC32 校验。主机 `--verify` 核对包全量摘要及逐帧校验码。
4. 网络执行器消费最新帧请求，在两个 28,800-byte PSRAM 像素缓冲间切换，继续由唯一显示任务分块差分绘制。页面离开停止读帧并释放缓冲；缺失、短读或校验失败使用原图回退，有限重试。V2 索引缺失时可以继续读旧 SD 的五段 `pet-v1.bin`，仅 V2 支持全目录和睡眠。
5. `display.stats.get` 可核对实际是否画出动画、片段／帧号、回退和绘出帧数。动作 ID 对应 `pet-v2.json`。真机以实际屏幕、操作时延、左右声道、音频连续、PSRAM／DMA、SD 缺失恢复和音乐并发分别验收。

未包含：可编辑语音转写、独立 TTS／音色设置、持久聊天记忆、图片对话、宠物无截止日期的待办编辑、触摸音效、梦话音频与动态效果开关。现有小智提供的会话能力取决于已激活的服务。下节是实施前可行性分析，保留历史条件。

## ESP32-S3 功能可行性（2026-11-11）

目标是一只在音箱上独立运行的桌宠。按用户取舍，不做多开、余额查询或 DSH 工作状态联动；保留完整素材归档，可把原工作状态片段借作本机「思考」等表情。宠物互撞随多开排除，屏幕边缘碰撞仍可做。截图里的桌面、浏览器及系统托盘入口是上游形态，以下按音箱行为评估；不自动采用截图里的后台请求或提醒规则。

| 能力 | 可行性与边界 |
| --- | --- |
| 全部 114 个动作、自定义素材 | ESP32-S3 可从 SD 播放离线转换后的片段。先做单角色资源包、带分类的点播和加权随机播放；后续可用相同包格式替换自制素材，无需引入多宠物框架。避免在设备实时解码 640×360 的透明 VP9。 |
| 点按、漫游、拖拽、甩抛、双击弹弓、边缘反弹与挤压 | 本地可做。触摸已提供坐标、按下状态，现有接口以 20 ms 为轮询目标，但当前手势消费只有离散事件，没有拖拽轨迹。现有传感所有者需发布有时间戳的有界触摸轨迹，显示任务将动作帧与位置／形变合成。左滑进应用列表优先；先验证普通拖拽、放下和反弹，再验证双击弹弓。桌面点按按既有优化方向用于角色互动。 |
| 倾斜、摇动 | MPU6050 已有姿态快照、倾斜零点和角速度，旧 Pebble 的控制器已有倾斜与快速转动反馈。当前图片路径只拷贝 RGB565，不使用位移和形变，需让新角色共享同一个运动输出。倾斜用姿态；要支持直线摇动时另从现有 IMU 所有者取加速度并做去重、去误触，不把现有角速度阈值当作完整摇动识别。碰撞画面反馈可做；现有产品配置未见触觉执行器，物理振动需另加硬件。 |
| 睡觉、气泡、动作菜单、点击音效 | 都可本地实现。睡觉只暂停随机动作和自动碎碎念，保留实际提醒和主动唤醒入口；可选梦话先用本地文字。用本机宠物动作菜单提供点播、聊天、睡觉／叫醒、回原位；保留右键长按全局助手。音效应可关闭，并经现有音频所有者避免干扰音乐或语音。 |
| 碎碎念、主动聊天、语音与记忆 | 离线能播本地气泡、配图和预录台词；生成对话、ASR、TTS 复用现有小智兼容路径，由服务决定支持的音色、文本提交和上下文能力。现有会话已有转写和说话状态，不等于可编辑转写、单句 TTS 或持久记忆已实现。可在设备显示短字幕，网页承载长历史／编辑转写；记忆须有大小上限、清除入口和唯一所有者。自动碎碎念默认安静，不自动开麦或打断正在播放的内容。若指让模型理解用户上传图片，需另外验证服务多模态接口。 |
| 待办、提醒与通知 | 复用产品已有时间和提醒记录。宠物气泡只展示真实待办或提醒，不复制可写状态。当前 Reminder 模型要求到期时间，无截止待办需要在同一业务域补建模。到点遵守已有一次提醒、对话中延后、关机错过标记规则；持续加密提醒或朗读可另设可选行为。以屏幕提示为主，系统通知中心和托盘对应音箱通知和网页管理入口。 |

主机小样：用 `ffmpeg -c:v libvpx-vp9` 对待机、点击、悬空、思考、碎碎念、睡眠六个归档片段采样，以 `fps=12,alphaextract` 分别得到 120 帧；均有透明区和非透明区，无空白帧。这验证了代表素材的离线透明解码，不证明全素材裁切、真机帧率或音频并发。160×160 RGB565 在 12 fps 下每路连续原始像素约 600 KiB/s；240×240 约 1.32 MiB/s，未计 alpha、解码、SPI 事务或 SD 并发开销。角色动作帧率与触摸位置更新可分开，优先让拖拽跟手，用最新位姿移动同一张帧。最终以不破坏音频和输入的真机结果定帧率与画幅。

建议第一条真机切片：待机呼吸 → 点击回应 → 竖向拖拽并松手回弹 → MPU6050 倾斜反馈 → 左滑进入列表；全程以 SD 播放音乐验证触摸不会改变播放意图，分别记录帧时延、DMA 余量和可闻断音。通过后沿同一播放路径接齐 114 段和点播目录，再扩展睡眠、语音、待办及个性设置。本轮为可行性评估和主机素材验证，未修改运行时或测真机。
