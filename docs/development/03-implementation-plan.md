# 分阶段实施计划

状态：推荐执行计划 v0.1，2026-11-10。所有阶段初始为“未按本计划验收”，不否认当前源码已有能力。每次执行先查最新记录和源码，复用已完成工作。

## 1. 执行方式

每个任务交付一个可运行或可检查的完整切片：输入 → 业务操作 → 结果 → 状态呈现 → 失败处理。不要先搭几十个抽象接口，再把真实功能推到最后。

允许为阶段演示使用明确标识的占位页面，但不得把占位记成业务完成。不因为某个外部服务未就绪而放弃其他可独立完成的部分；依赖服务的验收项准确标为待验证。

每阶段退出条件包括代码／文档证据与适用的验收项。没有真机时可以完成源码和主机验证，阶段标为“实现完成、待真机验收”，不能填写“已验收”。

## 2. 阶段总览

| 阶段 | 交付目标 | 主要依赖 | 对应验收 |
| --- | --- | --- | --- |
| P0 | 基线、复用来源、能力所有者、兼容性与风险清单 | 当前工程 | A-BASE、A-SOURCE |
| P1 | 真机 UI 骨架与统一交互 | P0 中 UI 所需结论 | A-UI、A-INPUT、A-WALL |
| P2 | 音乐与网页资源流程 | P1，现有音乐／上传 | A-MUSIC、A-WEB |
| P3 | 大肥鱼、手动单轮助手与音频协调 | P1、P2 的播放意图及音频边界 | A-AI、A-PET、A-FOCUS |
| P4 | 时间管理和信息看板 | P1，时间与存储结论 | A-TIME、A-REMIND、A-INFO |
| P5 | 游戏和双平台电脑采集 | P1，音频协调与遥测协议 | A-GAME、A-PC |
| P6 | 跨模块联合验收与交付收口 | 六模块及所需网页／采集端已实现 | A-RECOVERY、A-LOAD、A-RELEASE |

依赖只限制相关任务。例如 P4 的纯提醒规则可以先验证，不必等待云端语音上线；音频资源风险分析从 P0 开始，不拖到 P6。

## 3. P0：核对基线与完成接入决策

### 任务

1. 核对 `AGENTS.md`、基线修正记录、版本、SDK、依赖锁、引脚、组件闭包与当前工作区状态。保留用户修改，不以大规模 dirty diff 为理由清理工程。
2. 逐项追踪音乐、语音、音频焦点、显示、导航、输入、上传、持久化和网络的真实所有者与生命周期。明确哪些已接入、哪些仅有底层接口。
3. 对 AmoledOS 固定提交，记录许可、选用源码、HAL／字体／应用模型依赖和适配补丁边界；核对 LVGL 9.5.0 API 兼容性。
4. 固定大肥鱼素材来源和许可，按用户要求完整保存 dsh-pet 原始动画；先选代表片段验证设备格式，再生成覆盖全部动作的派生资源。保存原件不等同于设备可以播放。
5. 形成 P1 页面树和交互草案：桌面到列表入口、一级顺序、二层返回、触摸与旋钮焦点、全局浮层、设置入口。
6. 列出风险验证方案：单 UI 所有者、动画与音乐 SD 并发、共享 I²S 时钟、音频嵌套打断、网络与上传负载。
7. 补齐下方决策表中 P1 前必须确定的事项。电脑端技术栈、天气来源等可延后到其开发前，不以此阻塞 UI 骨架。

### 交付和退出条件

- 增加 `docs/development/implementation-status.md`，记录检查日期、实际版本、能力映射、差异、证据和风险；不得记录凭据、设备私密标识或复制本机日志。
- 上游固定信息写入 `docs/development/upstream-sources.md`；没有下载／核验的内容明确标为研究信息。正式引入源码时同步第三方声明。
- P1 任务已能按真实路径执行，未验证项有验证方法，不再依赖猜测接口。
- 本阶段默认以文档和检查为主。若必须做兼容性实验，限制在可独立删除的实验范围，不把实验实现冒充生产框架，不切换主桌面。

## 4. P1：UI 骨架优先

### 任务

1. 按固定来源接入 AmoledOS 必要 UI／导航代码，沿用现有 LVGL surface、flush 和显示任务。
2. 完成桌面、六模块纵向列表、二层选择、功能页容器和独立设置入口；三类桌面均有可识别的实际表现。
3. 完成按键、旋钮、触摸统一语义，长短按互斥，列表选择／数值编辑／播放器音量分场景处理。
4. 实现全局助手层和通知层的容器、进入退出和焦点恢复；未连接业务的入口明确说明状态。
5. 完成静态壁纸上传／预览／选择的最小完整流程；复用资源上传基础，故障保留原壁纸。
6. 形成 240×240 视觉规格：字体、行高、可见条目、图标尺寸、圆角、颜色、选中态、转场。附实际截图或可复现的模拟器画面，再做真机核对。

### 退出条件

- 从任意已接入业务页返回／回桌面无路由错乱，反复进入退出无持续内存损失。
- 列表风格符合上下滚动条目要求，触摸与实体输入可用，没有引入蜂窝布局。
- 现有音频、曲库、双声道和输入修复未被 UI 接入破坏；占位页面与已接入页面清楚区分。
- 提供真机视觉及手感验收证据；只有桌面模拟器时标待真机验收。

## 5. P2：音乐和网页完整流程

按“SD 本地曲库 → 播放 → 网页资源管理”逐个切片完成，不重写现有播放器。

1. 对接播放页与曲库：播放／暂停、切歌、音量、播放状态、空曲库及缺 SD。
2. 对接歌词、封面及关联规则，处理缺失、损坏、同名、替换及删除；先保留已有 MP3／LRC 兼容性，额外格式必须明确列为支持后再实现。
3. 白噪声使用同一音频通路，定义选择、开始、停止／循环和与音乐互斥规则。
4. 网页上传音乐／歌词／封面到 SD，提供进度、取消、失败及索引生效结果，验证中断不污染曲库。
5. 保留并接通 EQ／预设、输出保护、设置持久化和设备状态同步。
6. 建立播放意图版本及可被游戏／语音使用的暂停恢复接口；先在受控场景验证，不等待 P3 才设计。

退出条件：A-MUSIC、A-WEB 通过适用部分；网页刷新、页面退出不改变实际播放意图。音乐与原输入负载回归可用。

## 6. P3：大肥鱼与语音

建议先以少量素材验证真实负载，再扩充动画，避免先投入全部资源转换后发现渲染路径不可用。

少量素材仅限设备实验，原件已全量保存。交互按 [角色方案](06-pet-character.md) 适配：宠物桌面触摸优先用于互动，左滑进入应用列表，音乐控制边界随页面验证。

1. 接通现有麦克风／LunarLink 链路，验证 Board 绑定、bootstrap、采集、上传、回答文本与实际声音；不能以收到文本代替扬声器验收。
2. 实现手动发起、自动结束输入、回答后关闭麦克风的单轮策略，以及取消、无输入、断网、超时路径。
3. 实现宠物状态映射和有界动画预取；记录片段来源、转换步骤、资源清单及静态回退。
4. 打通全局对话层与宠物桌面的共享状态，正确返回来源页面。
5. 先让 AI 查询设备状态、控制现有音乐，再按已完成业务扩展番茄钟／提醒等工具。只有工具链路实际执行成功才报告成功。
6. 完成音频占用与恢复，包括 AI 改变播放意图、游戏内打开助手、取消和释放失败重试。
7. 网页完成必要 AI 配置与脱敏状态显示，不展示密钥明文快照。

退出条件：A-AI、A-PET、A-FOCUS 覆盖成功和故障路径。记录音乐＋动画的真实 SD／内存／刷新指标；没有云端凭据的部分标待服务验证，不伪造成功。

## 7. P4：时间与信息

1. 明确信任时间来源、时区、未校准状态、校时与断网行为；提供时钟显示。
2. 番茄钟支持开始、暂停、继续、结束，轮次／阶段持久化；重启恢复为暂停状态。
3. 提醒支持具体日期时间和按周重复，编辑／删除／处理事件有独立语义；接通本地、网页和 AI 工具的创建／查询／修改入口，使用同一记录。番茄钟同步接入网页与 AI 操作。
4. 实现待查看和已错过记录，防止重复触发；对话中只标记，结束后提示；开机错过不补响。
5. 月历显示日期与本地提醒标记；选定天气服务，接入地点、更新时间和过期状态。
6. 补齐同时到点、校时跳变、存储写失败、时区变更和多条通知的行为记录。

退出条件：A-TIME、A-REMIND、A-INFO 通过，包括可信时间建立前和重启后的行为，不接外部日历账户。

## 8. P5：娱乐和电脑协同

游戏与电脑采集是两个独立切片，按依赖分别完成。

1. 木鱼和 2048 均可实际操作；方向滑动与全局手势不冲突，音效及输入随前台／浮层暂停。
2. 进入游戏暂停音乐／白噪声，退出按意图恢复；完成游戏 → 助手 → 游戏 → 退出的嵌套验证。
3. 固定电脑端技术栈与指标库，分别验证 macOS、Windows 能力及权限边界。
4. 完成局域网发现或明确的手动连接流程、唯一电脑配对／替换、有版本遥测协议、断连与陈旧数据呈现。
5. 采集端提供托盘／菜单栏连接、状态、退出；交付可复现的开发运行和打包说明。
6. 验证权限不足、某些 GPU／温度／风扇不可采，设备显示原因，不显示假零值。

退出条件：A-GAME、A-PC 通过。只在一台系统运行不能宣布双平台完成；条件不足时分别标注两个系统的验证状态。

## 9. P6：联合验收

- 按验收清单执行全流程、故障恢复、资源与负载验证，重点是音乐＋动画＋网页／遥测的并发组合。
- 检查只有首发入口对用户开放；清除生产路径中的占位结果、假数据、废弃双实现和不可达入口。
- 保留有价值的诊断，确保凭据和设备证据未进入发布源码。
- 更新用户操作、资源准备、网页、电脑采集端、配置和已知限制文档。
- 记录每项“主机通过／构建通过／真机通过／待验证／失败”，并提供最终差异和风险说明。烧录、OTA、提交、推送和发布按实际授权分别执行。
